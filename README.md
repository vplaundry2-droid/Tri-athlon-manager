# Triathlon Manager

A browser-based triathlon management game. Build a fictional athlete through swimming, cycling, running, recovery and standard-distance races. No 3D engine, account, package installation or AI subscription is required to play.

**Playable alpha, not a medically validated training tool.** Injury probabilities, diagnoses, recovery windows and rehabilitation stages are gameplay assumptions, not individual medical predictions or treatment advice. In particular, a suspected femoral-neck bone stress injury does **not** automatically permit easy cycling.

## Play locally on Windows

Install Node.js 22 or newer, then double-click **Start Triathlon Manager.cmd**. Or open a terminal in this folder:

```sh
npm start
```

Open http://127.0.0.1:4173. Leave the server terminal open while playing. If the browser opens before startup finishes, refresh once. Progress is saved in that browser's storage; use **Save & settings → Export career** for backups or moving between the hosted and local app.

In GitHub Desktop choose **File → Add local repository** and select this folder. The repository can then be managed normally in Desktop.

## What's implemented

- Editable athlete: mass, height, body build, VO₂max, FTP, swim/run thresholds, starting CTL/ATL and independent sport durability. Optional measured drag area.
- Daily sessions, bricks, sleep/fueling choices, time budgets and early back-off. Requested training is limited by actual capacity; incomplete work never earns training load.
- Post-session debrief: planned vs completed duration, simulated RPE, pain separately, estimated TSS, session-RPE load, quality, distance/pace/power estimates, exhaustion/fuel/load changes and explanation of setbacks.
- CTL/ATL/Form history; fatigue and fuel are separate state, not synonyms for ATL.
- Shoulder, knee, Achilles, shin and lower-back cases; cumulative bone stress can trigger a suspected femoral injury. Multiple cases combine cross-sport restrictions.
- Protected recovery, simulated assessment, gradual rebuilding, return stages and final reassessment. Neglected rehabilitation, insufficient sleep/fuel and permitted-but-aggravating activity can delay healing. There is no guaranteed clearance date.
- Ongoing career, reproducible seeded traits, undo, autosave, JSON import/export and migration from the earlier v1/v2 prototype. Latest 180 debriefs, 90 chart days and 50 races are displayed/stored as applicable.
- Standard-distance race strategy: 1.5 km swim, 40 km bike, 10 km run; bike effort, hills, fuel and run pacing affect outcome. Underprepared or injured athletes cannot enter a forecast finish. Race completion applies load, fuel cost, tissue strain and exhaustion.
- Local rules coach, plus an **optional server-side AI narrator**. AI cannot edit state, clear injuries or execute sessions.

## Model boundaries and sources

Daily recurrence: `CTL += (estimatedTSS - CTL) / 42`; `ATL += (estimatedTSS - ATL) / 7`. Chart Form for day D is the previous evening's CTL minus ATL. The headline card shows Form for the next morning.

Sources: TrainingPeaks [CTL](https://help.trainingpeaks.com/hc/en-us/articles/204071884-Fitness-CTL), [ATL](https://help.trainingpeaks.com/hc/en-us/articles/204071894-Fatigue-ATL), [TSB/Form](https://help.trainingpeaks.com/hc/en-us/articles/204071764-Form-TSB).

Session load is a simplified `actual hours × intensity factor² × 100`, **not official rTSS or sTSS**. Session-RPE load is separately `actual minutes × simulated RPE`; see [Foster et al.](https://pubmed.ncbi.nlm.nih.gov/8693756/) and [session-RPE monitoring](https://pubmed.ncbi.nlm.nih.gov/11708692/). RPE is generated by the game; it is not an actual athlete measurement.

[AOSSM stress-fracture information](https://www.sportsmed.org/stress-fractures) and [AAOS stress-fracture overview](https://orthoinfo.aaos.org/en/diseases--conditions/stress-fractures) inform broad caution, **not the game's numerical thresholds or recovery durations**. Real recovery depends on exact location, severity and clinical assessment. CTL/ATL alone cannot diagnose injury or predict an individual's safe workload.

Physics: bike speed approximates aerodynamic drag, rolling resistance and gravity across flat/uphill/downhill segments. It omits wind, handling, braking, surface, temperature and equipment differences. Fitness adaptation, energy, tissue strain and injury progression are tunable heuristics. This is an alpha requiring gameplay calibration, not a promise of real-life accuracy or a commercial-ready release.

## Optional AI coach

The complete game works without AI. To enable AI **locally**, copy `.env.example` to `.env`, enter your own API key and an account-accessible model supporting Responses structured outputs, then start:

```sh
node --env-file=.env server.mjs
```

Keep `.env` private. It is ignored by Git. **Never put a key in public JavaScript, a save file or a GitHub issue.** An OpenAI API account with available billing is required; API charges are separate from a ChatGPT subscription. The server binds to loopback only and is not a public production API.

Each request requires the player's consent and button press. Only an allowlisted summary of game day, load, exhaustion/fuel, fictional injury stages, recent session and permitted choices is sent. Names, body profile and full history are excluded. The API request sets `store: false`; that does not mean zero provider retention. See OpenAI's [data controls](https://developers.openai.com/api/docs/guides/your-data). Responses use a [strict JSON schema](https://developers.openai.com/api/docs/guides/structured-outputs), server validation, timeouts, same-origin checks and a simple local rate limit. AI prose can still be wrong; it is explanatory only, not medical authority.

The static hosted build has **no AI backend or API keys**. Its local rules coach remains available. AI transport is covered by mocked tests; a real paid model call has not been verified without credentials.

## Development and tests

```sh
npm test
npm run build
```

`public/core.js` contains the physiological/physics approximation; `public/engine.js` owns career, reports, restrictions and recovery. `public/app.js` renders the UI. `server.mjs` serves public files and the optional AI endpoint. Node's built-in test runner covers the engine and server. No runtime dependencies.

`dist/` is a static deployment artifact; serve it with any static host. Relative assets support subdirectory hosting. The optional AI endpoint only exists when using `server.mjs`.

Save data stays on the player's device. No analytics, accounts or cloud save are implemented. Google Fonts are requested for typography; system fonts provide a fallback. Default athlete values are fictional. Future work: clinical review of model assumptions, richer periodization, more race distances, weather and event calendars, and broader playtesting.
